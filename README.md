# 江西省县域医共体 - 自动诊断候选

这是 `http://10.10.94.90:22112/radiation` 的 Tampermonkey 用户脚本项目。脚本在待诊断列表中按照可保存的过滤条件识别新记录，并优先使用业务接口校验后进入诊断页；取不到记录编号时才使用当前页面的诊断按钮回退。进入 `/radiation/report` 后仍保持 WebSocket、状态计数和只读列表观察，页面查询按钮只在 `/radiation` 列表页使用。进入前有状态安全门禁：记录必须仍是“待诊断”（当前状态码 `102501`）；锁定保护始终开启，旧配置和方案不能关闭；已锁定或页面显示“当前报告已被其他用户锁定”的记录直接跳过，不调用进入协议，也不点击诊断操作。

## 每份报告只进入一次与排除检查项目

- 自动进入记录按稳定报告编号独立持久化；退出后返回待诊断、刷新、升级、清空开发者日志和切换方案，都不会再次自动打开同一份报告。同名患者的新检查使用不同报告编号，可以正常处理。
- 进入被服务端明确拒绝时允许后续重试；已确认进入的记录不能被迟到旧响应清除。手工进入的当前账号报告成功载入后，也不再自动拉回。
- 在“检查与机构”的“排除项目”勾选肋骨平扫等项目，可搜索或添加自定义名称。允许项目选择“不限”时，排除规则仍然有效；多部位中任一项命中排除都会跳过。按规范化后的完整项目名称匹配。

## 运行方式

1. Edge 标准 CDP 端口为 `127.0.0.1:9333` 时，运行项目根目录的 `Update-Tampermonkey-Radiation.cmd`，直接保存到 Tampermonkey。
2. 更新器自动刷新 `/radiation` 列表页；不打开可见的扩展设置页。仅保存、不刷新时使用 `python update_tampermonkey_radiation_cdp.py --no-reload`。
3. 点击表头设置弹窗中的“自动诊断设置”，或使用 Tampermonkey 菜单打开设置。
4. 默认配置是：报告状态待诊断、年龄 18–40 岁、检查类型 CT、申请时间最近 5–30 分钟、检查项目按勾选项匹配、检查部位数量不限、申请机构不限、登录账号不限。
5. 首次测试建议保持“进入方式：协议优先（失败回退点击）”。如果只想观察已审核用户而不打开任何客户，关闭“启用自动打开”并保持“启用只读监控”；WebSocket、状态计数、只读列表和开发者诊断会继续运行，但不会调用进入协议或页面诊断按钮。
6. “开发者模式”默认开启，自动保留最近 1 小时（可配置）的完整调试记录，便于排查候选未及时进入；可在设置面板选择快捷时长或自定义分钟数，修改立即保存；也可复制或清空记录，关闭并保存后即停止记录。认证调试会记录 Cookie/Authorization 等凭证的存在性、长度和短哈希，不保存原始值或密码。

协议登录验证码说明：协议登录页面使用算式验证码（例如 `99-40=`），脚本可调用本机 OCR 服务自动识别并计算；门户登录的四位数字验证码仍兼容。协议登录请求会按业务前端发送 `Authorization`、`LOGIN-USER-KEY`、`LOGIN-USER-UID` 和 `LOGIN-CLIENT-IP`，并使用大写 `AUTH/LOGINCODE/WORKSTATION` 会话 Cookie，避免页面已登录但协议请求被判定为 `TOKEN_FAIL`。OCR 服务默认运行在 `http://127.0.0.1:18766`，先运行 `tools/start-captcha-ocr.ps1`，再检查 `/health`。启动脚本会先检查端口是否已经被其它本地服务占用；若占用，会明确停止并提示使用 `-Port 18767` 等空闲端口，然后在设置界面把 OCR 地址改为对应端口，避免两个服务抢同一个端口造成验证码请求随机失败。

## 持久化设置与日志

- 过滤设置和开发者开关修改后自动保存；刷新、脚本重载、代码升级均保留明确选择。
- 日志默认滚动保留一小时，可配置时长，按页面、分钟独立存储；旧页面较晚保存不能覆盖新页面记录。同源同步镜像弥补扩展写入延迟，清空操作对其它活动页面也有效。
- 协议校验通过后优先使用页面原生路由，不重新加载整个应用；最终进入响应到达前只阻止另一位客户进入，推送和列表观察照常。

## 快速定位进入异常

- `python -B tools/read-candidate-audit-cdp.py --name "客户姓名" --other-doctor "医生姓名"` 只读查询业务操作记录，超出日志保留时间的进入/锁定也可核对；不重放进入请求、不返回报告正文。
- `python -B tools/read-candidate-debug-cdp.py --name "客户姓名"` 直接读取当前 Tampermonkey 中该候选的保留时间线，不写入日志文件。
- “协议进入成功”带 `phase=assert-allowed`，只表示前置校验通过；“报告进入完成/拒绝/异常”来自报告页原生 `/api/ct/rays/rep/enter` 响应，才记录原生最终接口结果；GET 详情读取单独记录，不能据此宣称锁定成功。
- 普通事件每秒合并保存；进入结果、路由、版本和异常立即保存，离开页面前清空待写队列。每分钟清除过期事件，关闭开发者模式后仍清理旧数据。

## 性能策略

### 自动进入时段（当次选择有效）

- 在“启用自动打开”后提供四个快捷单选时段：08:00–12:00、12:00–14:30、14:30–17:30、17:30–次日 08:00。
- 点击即保存并开启自动进入；只允许选择一个时段。提前选未开始的时段，会等待开始时间；当天已结束的时段不能选择。
- 夜班在凌晨 08:00 前选择时属于昨晚开始的夜班，当天 08:00 到期；白天选择夜班则在当天 17:30 开始、次日 08:00 到期。
- 到期立即关闭自动进入并清除选择，必须再次点击时段才可启用。重载页面、切换筛选方案、导入配置或保存其它选项不会续期；只读监控继续运行。
- 旧配置尚未选择过时段时保持原有不限时行为；使用时段后，“关闭并清除”保持关闭，直到重新选择。截止边界按实际当前时间检查，已在等待/请求中的入口也不能越过截止时间导航。

### 只读监控与自动打开分离

- “启用只读监控”控制 WebSocket、`statusNum`、只读 `rep/list`、路由/会话自愈和开发者日志。默认开启。
- “启用自动打开”只控制进入诊断动作；关闭后，脚本仍可记录候选、过滤原因、锁定/状态变化和协议响应，并明确记录“观察模式跳过自动打开”，但不会调用 `assertAllowEnter`，也不会点击页面诊断操作。
- 该分离适合在用户已经打开某个审核/报告页面时做迭代测试，不会重置页面报告状态或抢占其它客户。恢复自动处理前，先在设置面板确认当前账号和过滤条件。

- 本地 DOM 扫描默认每 2 秒执行，不向服务器发请求。
- 页面加载时先复用业务页面已有的实时 WebSocket 推送作为主触发，不另建第二条业务 WebSocket；推送带完整报告编号时直接做协议进入校验。
- 推送字段不完整或协议校验失败时，按该条推送中的申请单号、患者、检查项目等线索读取窄列表；没有线索时才读取常规最新列表。
- 状态探测是兜底唤醒器：前台默认约 5 秒，最近收到 WebSocket 业务消息后自动降为至少 15 秒；隐藏标签页至少 15 秒，并带轻微随机抖动和失败退避，避免固定频率冲击服务器。
- 状态计数变化或 15 秒补偿窗口到达时才读取常规列表，默认最多读取 30 条、按申请时间倒序；申请时间范围会同步下传到列表请求，减少无关数据。
- 默认“最近 5–30 分钟”会先观察新申请，满 5 分钟后才允许进入，时间窗口每次请求都会随当前时间移动。
- 列表请求、协议校验和探测请求都有超时，并且禁止同类请求重叠；WebSocket 触发的列表调度窗口为 250ms，强制刷新冷却为 500ms。协议列表和状态探测会带上当前登录用户的组织 `oid`，避免接口返回 HTTP 200 但数据为空。开发者模式会把候选生命周期、首次/最近观察时间、过滤原因、入口等待、协议响应和前后状态变化关联到同一个候选标签。实时线索窄列表为空时，只对该条线索做一次按患者姓名的无组合筛选补全，拿到完整记录后再执行检查类型和其它规则。
- 进入诊断前再次确认报告状态仍为待诊断（当前状态码 `102501`）。设置中的“检测到其他用户锁定的记录时跳过”默认开启，开启后会检查列表记录或行操作的锁定标识；诊断中、待审核、审核中、已审核、已打印以及明确被其它用户锁定的记录不会调用进入协议或点击诊断按钮。关闭该选项只放宽客户端锁定跳过，仍要通过待诊断状态门禁和服务端允许进入校验；通过门禁后才使用业务路由打开页面，由诊断页继续完成系统锁定流程。
- 后台标签页不依赖表格 DOM：WebSocket、statusNum、列表查询和协议进入都可继续工作；浏览器被系统冻结、标签页被丢弃或浏览器关闭时，任何页面脚本都无法保证继续执行。
- 诊断中的入口锁只阻止自动进入第二个客户，不暂停右侧待诊断列表刷新、WebSocket 监听、状态探测或页面观察；列表中没有带诊断医生姓名的“诊断中”记录时，入口锁会自动释放。
- 表头过滤覆盖检查医院、检查部位、诊断医生和审核时间；这些选项会从当前列表动态生成复选框，留空或勾选“不限”表示不限制，并兼容旧配置。
- “更新所有可选项目”现在同时读取协议列表中的检查项目、检查医院、检查部位、诊断医生和申请机构，并缓存到配置，翻页或切换方案后仍可直接勾选。
- 开发者模式按时间保留最近 1 小时（可配置）流程事件，不再使用 240 条上限，并在控制台输出完整过滤原因、状态门禁、协议耗时、候选字段和认证上下文形状；认证上下文只含存在性、长度和短哈希，不含 Cookie、Authorization 原文或密码。

## 安全边界

脚本只读列表、状态计数和当前登录用户信息。关闭“启用自动打开”时只做只读监控，绝不会导航到诊断页；开启后，默认只有在报告状态严格为待诊断、未被其它用户锁定、匹配过滤规则且业务接口返回允许进入时才导航到诊断页。锁定保护始终开启，旧配置和方案不能绕过。脚本不修改服务器配置、不写入业务数据、不保存影像内容；开发者模式会在浏览器本地 `GM_*` 中滚动保存最近 1 小时（可配置）的完整候选调试记录，认证原文和密码不保存。

## 维护原则

- 先阅读 `docs/AI_HANDOFF.md`，再修改脚本。
- 以主文件为唯一源码来源；`reference/app-bundles` 只用于核对业务端接口，不直接修改。
- 修改后先运行 `node --check .\\jiangxi-radiation-auto-diagnose.user.js`。
- 不能把“源码已更新”当成“Tampermonkey 已加载”；必须在浏览器中确认脚本版本或实际日志。
- 不使用与本项目无关的 CTMW/EDW 探测脚本；不把临时密钥、Cookie、患者信息或截图放入项目。
