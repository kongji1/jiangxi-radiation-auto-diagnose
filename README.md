# 江西省县域医共体 - 自动诊断候选

这是 `http://10.10.94.90:22112/radiation` 的 Tampermonkey 用户脚本项目。脚本在待诊断列表中按照可保存的过滤条件识别新记录，并优先使用业务接口校验后进入诊断页；取不到记录编号时才使用当前页面的诊断按钮回退。进入前有状态安全门禁：记录必须仍是“待诊断”（当前状态码 `102501`），已经诊断中、已锁定或页面显示“当前报告已被其他用户锁定”的记录直接跳过，不调用进入协议，也不点击诊断操作。

## 运行方式

1. 在 Tampermonkey 中打开主文件的内容并保存。
2. 刷新业务页面 `/radiation`。
3. 点击表头设置弹窗中的“自动诊断设置”，或使用 Tampermonkey 菜单打开设置。
4. 默认配置是：报告状态待诊断、年龄 18–40 岁、检查类型 CT、申请时间最近 5–30 分钟、检查项目按勾选项匹配、检查部位数量不限、申请机构不限、登录账号不限。
5. 首次测试建议保持“进入方式：协议优先（失败回退点击）”，确认控制台出现“协议校验通过，打开诊断页”后再考虑切换为“仅协议”。
6. “开发者模式”默认关闭；本次从旧配置升级时会临时打开，便于排查候选未及时进入。打开后可在设置面板复制最近诊断记录，关闭并保存后即停止记录。

协议登录验证码说明：协议登录页面使用算式验证码（例如 `99-40=`），脚本可调用本机 OCR 服务自动识别并计算；门户登录的四位数字验证码仍兼容。OCR 服务默认运行在 `http://127.0.0.1:18766`，先运行 `tools/start-captcha-ocr.ps1`，再检查 `/health`。

## 性能策略

- 本地 DOM 扫描默认每 2 秒执行，不向服务器发请求。
- 页面加载时先复用业务页面已有的实时 WebSocket 推送作为主触发，不另建第二条业务 WebSocket；推送带完整报告编号时直接做协议进入校验。
- 推送字段不完整或协议校验失败时，按该条推送中的申请单号、患者、检查项目等线索读取窄列表；没有线索时才读取常规最新列表。
- 状态探测是兜底唤醒器：前台默认约 5 秒，最近收到 WebSocket 业务消息后自动降为至少 15 秒；隐藏标签页至少 15 秒，并带轻微随机抖动和失败退避，避免固定频率冲击服务器。
- 状态计数变化或 15 秒补偿窗口到达时才读取常规列表，默认最多读取 30 条、按申请时间倒序；申请时间范围会同步下传到列表请求，减少无关数据。
- 默认“最近 5–30 分钟”会先观察新申请，满 5 分钟后才允许进入，时间窗口每次请求都会随当前时间移动。
- 列表请求、协议校验和探测请求都有超时，并且禁止同类请求重叠。
- 进入诊断前再次确认报告状态仍为待诊断（当前状态码 `102501`），并检查列表记录或行操作是否已被锁定。诊断中、待审核、审核中、已审核、已打印以及“已被其他用户锁定”的记录不会调用进入协议或点击诊断按钮；通过门禁后才使用业务路由打开页面，由诊断页继续完成系统锁定流程。
- 后台标签页不依赖表格 DOM：WebSocket、statusNum、列表查询和协议进入都可继续工作；浏览器被系统冻结、标签页被丢弃或浏览器关闭时，任何页面脚本都无法保证继续执行。
- 开发者模式只在内存保存最近 240 条流程事件，并在控制台输出过滤原因、状态门禁（非待诊断/已锁定）、协议耗时和不可逆候选标签；不记录患者姓名、申请单号、报告编号或认证信息。

## 安全边界

脚本只读列表、状态计数和当前登录用户信息，只有在报告状态严格为待诊断、未被其它用户锁定、匹配过滤规则且业务接口返回允许进入时才导航到诊断页。脚本不修改服务器配置、不写入业务数据、不保存患者姓名或影像内容；认证头和用户信息只在当前页面内存中复用。`GM_*` 存储仅保存用户自己的过滤配置、方案和去重短键。

## 维护原则

- 先阅读 `docs/AI_HANDOFF.md`，再修改脚本。
- 以主文件为唯一源码来源；`reference/app-bundles` 只用于核对业务端接口，不直接修改。
- 修改后先运行 `node --check .\\jiangxi-radiation-auto-diagnose.user.js`。
- 不能把“源码已更新”当成“Tampermonkey 已加载”；必须在浏览器中确认脚本版本或实际日志。
- 不使用与本项目无关的 CTMW/EDW 探测脚本；不把临时密钥、Cookie、患者信息或截图放入项目。
