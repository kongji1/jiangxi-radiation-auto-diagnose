# 协议与负载说明

## 0.8.55 最终进入与原生响应交接

只有待诊断、项目规则及强制锁定门禁通过，且 `assertAllowEnter` 明确允许后，才继续进入。原生 Vue router、可识别的当前医生和响应交接桥可用时，脚本在导航前只发一次 `POST /api/ct/rays/rep/enter`，payload 与原生报告组件一致：`{repUid, isList: false, isRemote: false, flag}`；`flag` 在当前工作站严格等于 `105712` 时为 1，其余为 0。提前 POST 前确认原生 Pinia 登录码与会话 Cookie 一致，工作站须为与 Cookie 严格匹配的字符串；不能确认时保留原生导航进入流程。

最终取得要求 HTTP 成功、业务 `code=200`、对象数据和当前医生姓名精确一致；响应提供的报告编号须对应当前报告，提供的状态须为诊断中 `102502`，锁定拒绝信息始终阻断。明确被其它用户锁定的最终响应按报告持久保存 `server-locked-other`，不再自动尝试。其它明确业务拒绝可释放本次未确认消费；HTTP、网络、解析或归属无法确认时保留消费并持久暂停自动打开，提示核对当前诊断任务，不能继续自动取得另一份。明确业务拒绝或其它用户锁定拒绝才允许继续其它候选。最终 POST 禁用 `fetchJson` 的认证恢复重试，已经发出的尝试不能回退点击或再次发 POST。

完整业务包装响应只暂存在页面内存，交接票据最长 15 秒。原生报告页第一次相同 origin、报告 ID、payload、账号、会话和工作站的 XHR/fetch 请求消费同一响应，沿用原生编辑器和表单处理；同一已取得票据不能造成第二次锁定请求，已暂存票据的原生请求头异常会本地失败，不再发网络 POST。提前请求的旁听记录使用 `protocol-acquire-observed`，`finalReportLoaded=false`；当前报告页原生消费完成才记录最终载入。完整路由、会话或自动打开授权发生变化，以及交接失败、导航取消/异常，均保留取得结果并暂停自动打开，避免继续取得下一份；已确认取得后的原生交接消费异常/拒绝同样暂停并保留记录，不自动解锁。

明确业务拒绝必须同时满足 HTTP 成功、有限数字业务码且业务码不等于 200。HTTP 失败、业务码不明，以及 `code=200` 但数据或本人归属无效，均不能当作尚未取得报告，保留防重并暂停自动打开。

本地入口、传输交接和实时队列测试分别通过 49、28、17 项，107 项源码契约检查通过，全量维护为 `READY`。最终整包已保存并实际运行 `0.8.55`，启动时间 `2026-10-07T04:07:58.514Z`，源码与安装源码按 LF 计算的 SHA-256 严格一致；交接、会话和原生观察能力均已读回 ready。目前没有真实新候选的提前取得事件，临床正常载入及一次真实网络最终 POST 尚待验证；服务端锁定排他性仍须业务端保证。

## 端点

| 用途 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 当前登录用户 | GET | `/api/admin/user/info` | 首次协议请求按需读取 UID 和请求头所需用户信息，只读并仅驻留内存 |
| 最新列表 | POST | `/api/ct/rays/rep/list` | 只读，支持分页和状态/类型等筛选 |
| 状态计数 | POST | `/api/ct/rays/rep/statusNum` | 只读，返回各报告状态数量；脚本用它判断是否需要拉列表 |
| 页面实时提示 | WebSocket | `/api/ct/websocket?Authorization=...` | 页面自身已建立；脚本只观察新报告消息，不创建第二条连接 |
| 进入校验 | GET | `/api/ct/rays/rep/assertAllowEnter?repUid=...` | 只读校验，确认当前记录可被当前账号进入；只有状态门禁通过后才调用 |
| 原生报告详情读取 | GET | `/api/ct/rays/rep/enter/{repUid}/{isRemote}` | 仅在当前报告路由旁听，记录“报告详情读取”，不宣称锁定成功 |
| 报告最终进入 | POST | `/api/ct/rays/rep/enter` | 0.8.55 在交接能力可用时导航前取得一次，再向原生报告页交接完整响应；其它路径由原生页发起。业务码、数据和归属共同判断取得结果 |
| 诊断页 | GET 路由 | `/radiation/report?id=...&applyOrgCode=...` | 提前取得路径只使用 Vue router；原生页消费交接响应后确认载入。脚本继续观察列表，pending 与诊断中记录共同限制下一位进入 |

完整业务基址是 `http://10.10.94.90:22112`，脚本使用相对路径，避免写死不同会话的来源。

页面前端把当前会话的 `AUTH` Cookie 转为 `Authorization` 请求头，并附带 `LOGIN-USER-KEY`、`LOGIN-USER-UID`、`LOGIN-CLIENT-IP`、`WORKCODE` 和必要的 `USER-INFO`。脚本会在首次协议请求前按需读取当前登录用户信息，在内存中复用这些请求头，不保存认证值；直接协议登录的密钥、验证码、登录和用户信息请求也使用同一封装，并按应用约定写入大写 `AUTH/LOGINCODE/WORKSTATION` Cookie。前端包中的 `code: 2002` 对应 `TOKEN_FAIL`，遇到该返回时不能把它当成“没有候选记录”。

页面表格由业务前端的“查询”按钮刷新。0.8.2 在页面从后台恢复或窗口重新获得焦点时最多触发一次查询，等待短暂刷新后再扫描当前表格；这只用于把前台展示同步到最新状态，不是后台实时链路。

## 严格进入门禁（0.8.52）

锁定保护始终开启，旧配置 `skipLockedRecords=false` 和保存方案不能关闭。锁定标记、锁定医生姓名/UID、页面占用状态或禁用的诊断操作均直接拒绝；未知 WebSocket 状态先用现有窄列表只读补全，不能通过来源标记绕过待诊断检查。校验结果必须明确允许，且消息和数据没有锁定或非待诊断证据。校验返回后再次读取页面及原始记录，阻断期间状态改变的导航和按钮回退。

`实时列表请求发起` 只表示调度开始；以 `协议网络请求发起` 的 `networkStartedAt`/`hintToNetworkMs`/`withinOneSecond` 判断真实网络发送时间，`clientIpWaitMs` 和 `identityWaitMs` 区分本地准备。客户端 IP 失败缓存减少重复等待，不增加业务请求或后台轮询。

## 持久进入一次与检查项目排除（0.8.54）

自动进入以稳定 repUid 识别每份检查报告，不能以患者姓名、申请号或可变 DOM 复选框编号代替。每报告独立 GM key 与同源同步镜像保存预约/消费/确认状态，防止多文档整数组覆盖；它独立于开发者日志保留时长、清空和方案。记录补全后、异步校验后及点击前再次检查，已经进入的报告即使恢复待诊断也不能自动进入。同名的新报告编号独立处理。

明确最终 POST 业务拒绝可释放当前未确认尝试；其它用户锁定拒绝则持久阻断该报告。迟到旧请求不能擦除当前消费或确认。网络/解析异常不能证明尚未进入，保留消费避免重复。当前账号手工 POST 成功且报告路由/编号一致时同样标记；GET 详情或其它医生归属不确认。

`examNamesExcluded` 使用规范化完整项目名称精确匹配，遍历所有拆分部位；允许不限时排除仍生效，协议、异步补全和点击入口都检查。排除只影响客户端候选选择，不增加服务器请求。

## 进入加载互斥

自动发起进入后建立独立 sessionStorage pending，最长三十秒；当前报告本次原生消费完成、拒绝、错误、返回列表或到期才解除。期间仅拒绝另一位自动进入，继续列表和 WebSocket 观察。GET 详情、不同报告、提前取得响应和早于当前尝试的迟到响应不能释放 pending。0.8.55 提前取得路径只使用已有 Vue router，导航失败后清理票据并暂停自动打开，不回退完整页面导航；未提前取得的原生导航路径仍保留完整导航兜底。最终报告医生与当前账号不同时拒绝自动交接，不发起解锁或重新锁定。服务端并发锁定的排他性仍由业务系统负责。

## 进入结果诊断

`assertAllowEnter` 通过只表示可以打开报告页，不代表最终报告已载入。0.8.50 的观察桥在 document-start 安装，只旁听原生 XHR/fetch 的已完成响应，保留请求关联、HTTP/业务码、服务器消息和耗时，不复制请求头或报告正文。`协议进入成功` 带 `phase=assert-allowed`；原生最终接口看 `报告进入完成/拒绝/异常`；GET 详情接口单独记 `报告详情读取完成/拒绝/异常`，`finalReportLoaded` 还要求请求前后报告路由和编号一致。过滤和诊断互斥不受观察桥影响。

## 列表请求原则

主脚本的 `radiationListPayload()` 保持页面原始字段结构，重要字段包括：

### 状态探测兼容性

`/api/ct/rays/rep/statusNum` 只发送不带状态、检查类型和机构筛选的全局计数请求。现场抓包确认，带 `reportStatusCodeList` 的状态探测会返回 `code=2002`，使轮询退避并延迟发现新申请。状态计数只负责唤醒轮询，待诊断、锁定、年龄、检查项目和机构规则统一在客户端判断。列表请求遇到同样的 `2002` 时自动退回最近列表并在客户端过滤；如果受控恢复仍失败且当前页面可用，会调用一次页面原生查询让业务 Axios 重新提供会话头。该兜底复用 15 秒查询闸门，不建立高频重试。

- `pageNum: 1`
- `pageSize`：普通探测最多 30；手工更新项目最多 100；协议兜底按匹配条件最多 20
- `sortByParams: [{ sortField: 'checkinTime', sortRule: 'DESC' }]`
- `reportStatusCodeList`、`modalityList`、`applyOrgName`：根据当前过滤条件收窄范围
- `checkinStartTime`、`checkinEndTime`：由申请时间规则实时换算；例如“最近 5–30 分钟”会只请求当前时间往前 5 到 30 分钟的窗口
- 其它页面表单字段保留空值，避免改变业务端默认语义

服务器探测先使用 `statusNum`，把结果对象按键排序后计算 JSON hash。第一次只建立基线；后续状态计数变化时读取列表。页面已有的 `/api/ct/websocket` 推送是主触发，脚本只在当前页面世界注入观察桥，不创建第二条业务连接；推送带有完整报告编号和过滤字段时，先检查报告状态和锁定信息，再进入允许性校验，字段不足或校验失败时按推送线索读取窄列表。即使没有推送，默认每 15 秒做一次列表补偿，避免“总数不变但新记录替换旧记录”时漏检。

后台标签页也走同一条协议链路，不要求表格已经渲染或用户点击“查询”。锁定保护始终开启；只有报告仍为待诊断且没有锁定证据时，才可触发 `assertAllowEnter` 和诊断路由。旧配置中的关闭值会被归一为开启，不能绕过客户端门禁。状态探测在隐藏标签页至少 15 秒一次，且最近收到实时业务消息时会自动降频。浏览器的页面冻结/丢弃机制仍可能暂停所有脚本，这是浏览器生命周期限制，不能由用户脚本绕过。

申请时间窗口会在每次请求前按当前时间重新计算。例如默认“最近 5–30 分钟”下，刚推送的新申请会被立即观察到，但在满 5 分钟前不会进入诊断；随后由状态变化、实时提示或列表补偿重新检查，进入可用窗口后才执行协议进入。

## 记录识别

`recordData()` 把协议记录转换为页面行使用的同一过滤结构：

- `repUid` → 去重主键和协议进入编号
- `patName`、`gender`、`patAge` → 患者条件
- `reportStatusCode`/`checkStatusCode` → 状态门禁依据；必须等于当前待诊断值 `102501`
- `reportStatus` → 报告状态文字；只作为兼容显示，不能用模糊包含替代状态码判断
- `isLock`/`isLocked`/`locked`/`lock`/`lockedByOther`/`lockStatus`/`lockUser`/`lockUserName`/`lockReason`/`occupyStatus`/`occupyUser`/`isOccupied` 及行的禁用标识 → 锁定门禁；明确属于其它用户占用、诊断中或操作项禁用时直接跳过。列表原始记录目前已确认包含 `isLock`，页面通常以解锁图标表示占用。
- `modality` → 检查类型
- `checkinTime` → 申请时间匹配
- `examName` → 检查项目/部位数量匹配
- `applyOrgName` → 申请机构
- `reportDoc`、`auditDoc` → 医生条件

若页面 DOM 行有 Vue 组件引用，脚本会优先从行附近读取真实记录；取不到时才用受限条件查询 `rep/list`，不会扫描整棵组件树。

## 负载保护

- `probeRunning`、`listRefreshRunning` 和进入互斥标志防止同类任务重叠或连续打开两条记录；实时线索在请求重叠或冷却时会排队保留。
- 进入协议前必须通过严格待诊断及强制锁定门禁。状态不是 `102501` 或存在锁定证据时始终不调用 `assertAllowEnter`；页面点击回退也不能绕过，异步校验返回后仍须再次检查。
- 状态探测前台默认 5 秒，带约 ±15% 抖动；最近有实时消息或页面隐藏时至少 15 秒；连续失败按 2 倍退避，最长约 60 秒。
- 普通列表补偿默认 15 秒；空闲首条实时提示立即调度，频繁提示保留 250ms 合并边界，最短请求冷却仍为 500ms。列表在途时保存精确线索和首次提示时间，由请求 `finally` 唤醒；单次请求约 5 秒超时。
- DOM 扫描只在前台执行；协议探测、WebSocket 处理和列表请求在隐藏标签页仍可执行。当前路径不是 `/radiation` 时不再启动候选处理。
- 进入方式为“页面点击”时不使用远端协议探测，避免无意义请求。
